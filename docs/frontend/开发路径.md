# 前端开发路径

> 目标：以现有后端能力为边界，把 `frontend/原型.html` 拆成可启动、可联调、可验收的前端工程。
> 原则：每个阶段都有可运行产物；没有后端支撑的交互不进入本期范围，不用静态假数据伪装完成。
> 依据：`docs/frontend/总体方案.md`、`docs/接口文档.md`、`docs/backend/开发路径.md`。

## 阶段 0：原型审计与接口对齐

### 目标

确认原型中哪些视觉与交互可以复用，哪些需要后端能力支撑，形成页面与接口的唯一映射表。

### 任务

- 盘点原型页面结构、组件清单、断点与交互行为
- 对照 `docs/接口文档.md` 逐页标注真实接口或静态归属
- 标记购物车、收藏、会员价、地址、普通订单为暂不实现
- 确定字体、图片、图标的本地化与加载失败兜底策略
- 确定字段口径：商品侧 `id`、搜索侧 `productId`

### 产出

- `docs/archive/frontend-拆分任务/阶段0/任务拆分.md`
- 页面接口映射表（写入 `接口对齐.md`）

### 验收

- 每个首期页面都有明确接口，或明确标注为静态内容
- 没有把不存在的后端接口写成需求
- 原型中不可落地的交互有明确处置结论

---

## 阶段 1：工程骨架与设计令牌

### 目标

得到一个能启动、能路由、能请求、能在桌面与移动端正常渲染的空业务前端。

### 任务

- 初始化 Vite + Vue 3 + TypeScript 工程
- 配置路径别名、环境变量、ESLint 与格式化
- 抽取原型设计令牌到全局样式：颜色、字体、间距、圆角、动效、断点
- 搭用户侧与管理端两套布局骨架
- 建立 HTTP 客户端、统一响应解析、业务错误类型
- 建立 Pinia 登录态存储与路由守卫骨架

### 产出

- 可运行的开发服务器与构建产物
- `src/styles/tokens.css`、`src/styles/base.css`
- `src/api/http.ts`、`src/api/types.ts`
- `src/layouts/SiteLayout.vue`、`src/layouts/AdminLayout.vue`
- `src/stores/auth.ts`、`src/router/index.ts`

### 验收

- 开发服务器可启动，`/`、`/admin` 可访问
- 设计令牌取值与原型一致
- `vue-tsc` 类型检查与 `vite build` 通过
- 移动端断点下布局不出现横向溢出

---

## 阶段 2：认证与基础商品

### 目标

完成登录、登录态恢复、商品列表与商品详情，跑通第一条真实数据链路。

### 任务

- 登录页与表单校验
- 令牌保存、刷新页面恢复登录态、退出登录
- 路由守卫与 HTTP 401 / 403 统一处理
- 商品列表：分页、关键字、分类 ID
- 商品详情：真实字段、下架商品错误处理
- 通用组件：商品卡片、价格、库存、状态标签、空状态、分页、骨架

### 产出

- `/login`、`/me`、`/products`、`/products/:id`
- `src/api/product.ts`、`src/api/auth.ts`
- `src/features/product/*`、`src/features/auth/*`

### 验收

- 登录成功后能读到当前用户
- 刷新页面登录态不丢
- 商品列表分页与筛选结果与接口一致
- 下架商品显示业务错误而非空白页

---

## 阶段 3：AI 混合搜索

### 目标

把原型的本地建议升级为真实 BM25 + 向量 + RRF 混合搜索。

### 任务

- 公共搜索框组件与搜索建议
- `/search` 页面，关键词与分页同步到 URL
- 搜索结果卡片按 `productId` 跳转详情
- 业务码 `3001` / `3002` 的差异化处理
- 空结果、加载中、服务不可用三种状态

### 产出

- `/search`
- `src/api/search.ts`
- `src/features/search/*`
- `src/components/SearchInput.vue`

### 验收

- 自然语言查询能展示真实召回结果
- 浏览器前进后退能恢复搜索条件
- 搜索错误不会被展示成“没有商品”

---

## 阶段 4：秒杀用户侧闭环

### 目标

完成活动列表、活动详情、抢购、结果轮询、订单详情与模拟支付。

### 任务

- 秒杀活动列表与进行中筛选
- 活动详情与四种活动状态展示
- 抢购按钮的登录校验与重复提交保护
- 抢购结果状态机与可取消轮询
- 订单详情、待支付倒计时
- 模拟支付与状态同步
- 页面离开时停止轮询

### 产出

- `/seckill`、`/seckill/:activityId`、`/seckill/:activityId/result`、`/orders/:orderNo`
- `src/api/seckill.ts`
- `src/features/seckill/*`
- `src/composables/useSeckillPolling.ts`、`src/composables/useCountdown.ts`

### 验收

- 抢购受理成功不会直接显示“下单成功”
- `QUEUING`、`SUCCESS`、`FAILED` 三种结果都能正确展示
- 轮询不会重复启动，离开页面即停止
- 轮询超时后允许重新查询而不伪造成失败
- 订单支付后按钮与状态同步变化

---

## 阶段 5：管理端

### 目标

完成商品与秒杀活动的后台维护页面。

### 任务

- 管理端路由与 ADMIN 权限守卫
- 商品列表、新增、编辑、上下架
- 商品图片上传与预览
- 秒杀活动列表、创建、编辑
- 表单校验与业务码提示
- 搜索索引重建操作入口

### 产出

- `/admin`、`/admin/products*`、`/admin/seckill*`
- `src/api/admin.ts`
- `src/features/admin/*`

### 验收

- 普通用户进入管理端被拦截
- 新增商品默认下架，上架后用户侧可见
- 图片上传成功后可预览且 URL 可访问
- 活动时间与价格校验与后端一致

---

## 阶段 6：验收与优化

### 目标

从“能点”提升为“可交付”，沉淀真实联调记录。

### 任务

- 关键流程端到端测试
- 移动端、键盘操作、减少动效检查
- 首屏图片与字体加载优化
- 错误边界、空状态、加载骨架补齐
- 联调记录与验收结果沉淀

### 产出

- `tests/e2e/*`

### 验收

- 首页、搜索、秒杀闭环、订单、管理端关键路径可运行
- 桌面与移动端均可操作
- 401、403 与主要业务码均有明确反馈
- 验收数据全部来自真实联调

---

## 阶段依赖与提交策略

- 阶段 2 依赖阶段 1 的 HTTP 客户端与布局
- 阶段 4 依赖阶段 2 的登录态
- 阶段 5 依赖阶段 2 与阶段 4 的接口函数
- 阶段 6 依赖阶段 0 到阶段 5 全部完成

提交信息格式沿用仓库约定 `<type>: <精炼描述>`；每个阶段结束时回填实测结果，数据必须来自真实运行。
