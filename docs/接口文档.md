> 文档归属：前后端公用  
> 适用版本：当前仓库后端接口  
> 接口定义以运行中的 OpenAPI 文档为准，本文补充鉴权、错误处理、业务状态和联调约定。

## 1. 文档入口

| 类型 | 地址 | 用途 |
| --- | --- | --- |
| Swagger UI | `http://localhost:8080/swagger-ui/index.html` | 查看、调试接口 |

## 2. 基础约定

### 2.1 服务地址

- Base URL：`http://localhost:8080`
- 业务接口前缀：`/api`
- 请求与响应编码：`UTF-8`
- JSON 请求头：`Content-Type: application/json`

### 2.2 鉴权

登录成功后，把令牌放入请求头：

```http
Authorization: Bearer <token>
```

权限分为：

| 角色 | 说明 |
| --- | --- |
| 游客 | 可访问公开的商品、搜索和秒杀活动查询接口 |
| `USER` | 登录后可抢购、查询自己的抢购结果、查询订单和模拟支付 |
| `ADMIN` | 可访问管理端商品、搜索索引和秒杀活动维护接口 |

令牌默认有效期为 120 分钟，实际值由后端 `JWT_EXPIRE_MINUTES` 配置决定。

### 2.3 统一响应

```json
{
  "code": 0,
  "message": "成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | integer | 业务码，`0` 表示成功 |
| `message` | string | 提示信息 |
| `data` | any | 业务数据，失败时通常为 `null` |

注意：

- 业务失败可能仍返回 HTTP `200`，前端必须同时检查 HTTP 状态码和业务码。
- 认证失败和权限不足分别返回 HTTP `401`、`403`，响应体仍使用上述统一结构。
- 参数校验失败返回 HTTP `400`。

### 2.4 分页响应

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "total": 100,
    "page": 1,
    "size": 10,
    "list": []
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `total` | long | 总记录数 |
| `page` | long | 当前页码，从 1 开始 |
| `size` | long | 每页条数 |
| `list` | array | 当前页数据 |

### 2.5 时间与金额

- 时间格式：ISO 8601 本地时间，例如 `2026-10-17T10:00:00`
- 金额：JSON 数字，建议前端展示时统一保留两位小数
- 时区：`Asia/Shanghai`

## 5. 商品接口

### 5.1 商品模型

```json
{
  "id": 1,
  "name": "轻量网面透气跑步鞋",
  "brand": "沃兰",
  "categoryId": 1001,
  "description": "适合日常通勤与轻量跑步。",
  "sellingPoint": "网面透气 轻量缓震",
  "price": 399.0,
  "stock": 100,
  "status": 1,
  "imageUrl": "http://localhost:9000/mall-product/..."
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | long | 商品 ID |
| `name` | string | 商品名称 |
| `brand` | string/null | 品牌 |
| `categoryId` | long | 分类 ID |
| `description` | string/null | 商品描述 |
| `sellingPoint` | string/null | 卖点 |
| `price` | number | 售价 |
| `stock` | integer | 库存 |
| `status` | integer | `1` 上架，`0` 下架 |
| `imageUrl` | string/null | 商品图片 URL |

### 5.2 用户查询商品列表

`GET /api/products`

公开接口，只返回上架商品。

查询参数：

| 参数 | 类型 | 必填 | 默认值 | 约束 |
| --- | --- | --- | --- | --- |
| `page` | integer | 否 | `1` | 最小 1 |
| `size` | integer | 否 | `10` | 1 到 100 |
| `keyword` | string | 否 | - | 最长 64，匹配名称或品牌 |
| `categoryId` | long | 否 | - | 正数 |

示例：

```text
GET /api/products?page=1&size=10&keyword=跑步&categoryId=1001
```

响应数据为分页商品结构。

### 5.3 用户查询商品详情

`GET /api/products/{id}`

公开接口。下架或不存在的商品统一返回业务码 `2001`。

### 5.4 管理员查询商品

`GET /api/admin/products`

需要 ADMIN。参数与用户查询相同，额外支持：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `status` | integer | 否 | `0` 下架，`1` 上架；不传表示全部 |

### 5.5 新增商品

`POST /api/admin/products`

需要 ADMIN。新增后默认下架，需要再调用上下架接口。

```json
{
  "name": "缓震竞速跑鞋",
  "brand": "沃兰",
  "categoryId": 1001,
  "description": "碳板中底，适合半马与全马竞速。",
  "sellingPoint": "碳板 竞速缓震",
  "price": 1099.0,
  "stock": 30,
  "imageUrl": null
}
```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `name` | string | 是 | 非空，最长 128 |
| `brand` | string | 否 | 最长 64 |
| `categoryId` | long | 是 | 非空 |
| `description` | string | 否 | 最长 2000 |
| `sellingPoint` | string | 否 | 最长 255 |
| `price` | number | 是 | 大于 0，最多 8 位整数、2 位小数 |
| `stock` | integer | 是 | 大于或等于 0 |
| `imageUrl` | string | 否 | 最长 512 |

成功响应的 `data` 为商品模型。

### 5.6 编辑商品

`PUT /api/admin/products/{id}`

需要 ADMIN。所有字段均可选，字段为 `null` 表示不修改。

```json
{
  "price": 999.0,
  "sellingPoint": "碳板 竞速缓震 轻量"
}
```

字段约束与新增商品一致，但不能通过本接口修改上下架状态。

### 5.7 上架或下架

`PATCH /api/admin/products/{id}/status`

需要 ADMIN。

```json
{
  "status": 1
}
```

重复设置当前状态会返回业务码 `2002`。

### 5.8 上传商品图片

`POST /api/admin/products/images`

需要 ADMIN，使用 `multipart/form-data`：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `file` | file | 是 | png、jpg、gif、webp，最大 5 MB |

成功响应的 `data` 是可直接访问的图片 URL 字符串：

```json
{
  "code": 0,
  "message": "成功",
  "data": "http://localhost:9000/mall-product/2026/10/17/xxx.png"
}
```

## 6. 搜索接口

### 6.1 混合搜索

`GET /api/search`

公开接口。后端同时执行 BM25 关键词召回和向量语义召回，再用 RRF 融合。

查询参数：

| 参数 | 类型 | 必填 | 默认值 | 约束 |
| --- | --- | --- | --- | --- |
| `keyword` | string | 是 | - | 非空，最长 128 |
| `page` | integer | 否 | `1` | 最小 1 |
| `size` | integer | 否 | `10` | 1 到 50 |

示例：

```text
GET /api/search?keyword=夏天穿的透气鞋&page=1&size=10
```

搜索结果条目：

```json
{
  "productId": 1,
  "name": "轻量网面透气跑步鞋",
  "brand": "沃兰",
  "categoryId": 1001,
  "sellingPoint": "网面透气 轻量缓震",
  "price": 399.0,
  "stock": 100,
  "imageUrl": "http://localhost:9000/mall-product/...",
  "score": 0.016,
  "hasVector": true
}
```

注意：

- 搜索结果的主键字段是 `productId`，不是 `id`。
- `score` 是 RRF 融合分，主要用于调试排序，不建议直接展示为业务评分。
- `hasVector` 表示该商品文档是否已有语义向量。

### 6.2 重建搜索索引

`POST /api/admin/search/reindex`

需要 ADMIN。成功响应的 `data` 为重建的商品数量。

## 7. 秒杀接口

### 7.1 活动模型

```json
{
  "id": 1,
  "productId": 1,
  "title": "限时秒杀",
  "seckillPrice": 199.0,
  "originalPrice": 399.0,
  "totalStock": 10,
  "remainingStock": 8,
  "perUserLimit": 1,
  "startTime": "2026-10-17T10:00:00",
  "endTime": "2026-10-17T12:00:00",
  "status": 1
}
```

活动状态 `status`：

| 值 | 含义 |
| --- | --- |
| `0` | 未开始 |
| `1` | 进行中 |
| `2` | 已结束 |
| `3` | 已关闭 |

### 7.2 查询活动列表

`GET /api/seckill/activities`

公开接口。

| 参数 | 类型 | 必填 | 默认值 | 约束 |
| --- | --- | --- | --- | --- |
| `page` | integer | 否 | `1` | 最小 1 |
| `size` | integer | 否 | `10` | 1 到 100 |
| `runningOnly` | boolean | 否 | - | `true` 时只返回进行中的活动 |

### 7.3 查询活动详情

`GET /api/seckill/activities/{activityId}`

公开接口。

### 7.4 抢购

`POST /api/seckill/{activityId}`

需要登录，不需要请求体。

成功响应表示请求已经被 Redis 受理：

```json
{
  "code": 0,
  "message": "成功",
  "data": null
}
```

该响应**不代表订单已经创建**。前端收到成功后必须轮询抢购结果接口。

### 7.5 轮询抢购结果

`GET /api/seckill/{activityId}/result`

需要登录。返回当前用户在指定活动下的结果。

排队中：

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "state": "QUEUING",
    "orderNo": null,
    "productName": null,
    "seckillPrice": null,
    "status": null,
    "expireTime": null
  }
}
```

抢购成功：

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "state": "SUCCESS",
    "orderNo": "SK1792243963220-2-125",
    "productName": "轻量网面透气跑步鞋",
    "seckillPrice": 199.0,
    "status": 1,
    "expireTime": "2026-10-17T10:15:00"
  }
}
```

未抢到：

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "state": "FAILED",
    "orderNo": null,
    "productName": null,
    "seckillPrice": null,
    "status": null,
    "expireTime": null
  }
}
```

`state` 取值：

| 值 | 前端处理 |
| --- | --- |
| `QUEUING` | 继续轮询 |
| `SUCCESS` | 使用 `orderNo` 进入订单详情或支付流程 |
| `FAILED` | 展示未抢到结果 |

轮询间隔和最大时长属于前端策略，后端没有规定固定值。建议采用递增间隔或设置页面级超时，并在超时后允许用户重新查询结果。

### 7.6 查询秒杀订单

`GET /api/seckill/orders/{orderNo}`

需要登录。

```json
{
  "code": 0,
  "message": "成功",
  "data": {
    "orderNo": "SK1792243963220-2-125",
    "activityId": 1,
    "productId": 1,
    "productName": "轻量网面透气跑步鞋",
    "seckillPrice": 199.0,
    "status": 1,
    "expireTime": "2026-10-17T10:15:00",
    "payTime": null
  }
}
```

订单状态 `status`：

| 值 | 含义 |
| --- | --- |
| `1` | 待支付 |
| `2` | 已支付 |
| `3` | 已取消 |
| `4` | 超时取消 |

订单号格式为 `SK` + 毫秒时间戳 + `-` + 用户 ID + `-` + 活动 ID，例如 `SK1792243963220-2-125`。
拼接段保证不同用户、不同活动不撞号；时间戳段保证取消后重新下单会拿到新单号。
前端只应把订单号当字符串透传，不要解析或自行拼接。

注意：当前后端订单查询按订单号查询，接口本身未额外比对订单归属用户。

### 7.7 模拟支付

`POST /api/seckill/orders/{orderNo}/pay`

需要登录，不需要请求体。仅待支付订单可以支付，成功返回更新后的订单。

### 7.8 管理员创建活动

`POST /api/admin/seckill/activities`

需要 ADMIN。

```json
{
  "productId": 1,
  "title": "网面透气跑步鞋 限时秒杀",
  "seckillPrice": 199.0,
  "totalStock": 10,
  "perUserLimit": 1,
  "startTime": "2026-10-17T10:00:00",
  "endTime": "2026-10-17T12:00:00",

```

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| `productId` | long | 是 | 必须是上架商品 |
| `title` | string | 是 | 非空，最长 128 |
| `seckillPrice` | number | 是 | 大于 0，且必须低于商品原价 |
| `totalStock` | integer | 是 | 大于 0 |
| `perUserLimit` | integer | 否 | 大于 0，默认 1 |
| `startTime` | string | 是 | 开始时间 |
| `endTime` | string | 是 | 必须晚于开始时间 |
| `payTimeoutMinutes` | integer | 否 | 大于 0，默认 15 |

### 7.9 管理员编辑活动

`PUT /api/admin/seckill/activities/{activityId}`

需要 ADMIN。字段为 `null` 表示不修改。

## 8. 业务错误码

| 业务码 | 含义 | 常见 HTTP 状态 |
| --- | --- | --- |
| `0` | 成功 | 200 |
| `400` | 请求参数不合法 | 400 |
| `401` | 未认证或登录已过期 | 401 |
| `403` | 权限不足 | 403 |
| `404` | 资源不存在 | 404 |
| `500` | 系统内部错误 | 500 |
| `1001` | 用户名或密码错误 | 200 |
| `1002` | 用户不存在 | 200 |
| `1003` | 账号已被禁用 | 200 |
| `2001` | 商品不存在 | 200 |
| `2002` | 商品状态不合法 | 200 |
| `2003` | 图片上传失败 | 200 |
| `3001` | 文本向量化失败 | 200 |
| `3002` | 搜索服务暂不可用 | 200 |
| `4001` | 秒杀活动不存在 | 200 |
| `4002` | 秒杀活动尚未开始 | 200 |
| `4003` | 秒杀活动已结束 | 200 |
| `4004` | 秒杀商品已售罄 | 200 |
| `4005` | 同一活动每人限购一件 | 200 |
| `4006` | 秒杀订单不存在 | 200 |
| `4007` | 订单状态不允许该操作 | 200 |
| `4008` | 活动时间不合法 | 200 |
| `4009` | 秒杀价必须低于商品原价 | 200 |
| `4010` | 排队服务暂不可用 | 200 |
| `4011` | 抢购请求处理中（当前后端未抛出，见下方说明） | 200 |

前端处理建议：

- `401`：清理本地令牌并跳转登录。
- `403`：提示无权限，不反复重试。
- `4004`、`4005`：展示明确的业务结果，不当作网络故障。
- `4010`：提示稍后重试，抢购请求可以重新发起。
- 其他非零业务码：展示后端 `message`，并记录必要日志。

### 8.1 秒杀业务码触发条件与可达性

以下为实测确认的触发条件（`backend` 侧代码路径与真实响应均已核对）：

| 业务码 | 触发条件 | 实测响应 |
| --- | --- | --- |
| `4001` | 活动 ID 不存在 | `{"code":4001,"message":"秒杀活动不存在"}` |
| `4002` | 活动时间窗口尚未开始（`startTime` 在未来） | `{"code":4002,"message":"秒杀活动尚未开始"}` |
| `4003` | 活动时间窗口已结束（`endTime` 在过去） | `{"code":4003,"message":"秒杀活动已结束"}` |
| `4004` | Redis 库存扣到 0 后继续抢购 | `{"code":4004,"message":"秒杀商品已售罄"}` |
| `4005` | 同一用户在买家集合中已有记录 | `{"code":4005,"message":"同一活动每人限购一件"}` |
| `4010` | RocketMQ 生产者创建或消息投递失败（如 proxy 不可用） | `{"code":4010,"message":"排队服务暂不可用，请稍后重试"}` |

`4002`、`4003`、`4004`、`4010` 均可稳定复现；`4010` 触发时后端会回补 Redis 预扣，
实测活动 `remainingStock` 恢复到与 `totalStock` 一致，且 `/result` 返回 `FAILED`，不会留下占用。

`4011` 当前**不可达**：`ResultCode.SECKILL_QUEUING` 在代码中仅有一处常量定义，
没有任何抛出点。前端仍保留该码的独立文案与分支，以便后端将来启用时无需改前端；
联调与验收时不应把 `4011` 计为已验证。

## 9. 联调检查清单

- 后端健康检查可访问：`GET /actuator/health`
- Swagger UI 可打开：`GET /swagger-ui/index.html`
- 登录后可访问 `/api/auth/me`
- 普通用户访问管理端返回 `403`
- 商品新增后默认下架，上架后才出现在用户商品列表
- `POST /api/seckill/{activityId}` 成功后继续轮询 `/result`
- 轮询只在 `QUEUING` 时继续，在 `SUCCESS` 或 `FAILED` 时停止
- 所有响应统一检查 HTTP 状态码与 `code`
