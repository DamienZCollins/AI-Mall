## 1.4 HTTP 客户端

- [x] `src/api/http.ts` 基于 axios 创建实例，`baseURL` 取 `import.meta.env.VITE_API_BASE_URL`，缺失时启动即报错
- [x] `src/api/types.ts` 定义 `ApiResponse<T> = { code: number; message: string; data: T }` 与 `PageResult<T> = { total: number; page: number; size: number; list: T[] }`
- [x] 定义 `ApiError`：携带 `code`、`message`、`httpStatus`、`kind`（`business` / `http` / `timeout` / `network` / `canceled`）
- [x] 请求拦截：令牌存在时附加 `Authorization: Bearer <token>`
- [x] 响应拦截：先判 HTTP 状态码，再判 `code`；`code !== 0` 抛 `ApiError` 并保留后端 `message`
- [x] HTTP `401`：清空登录态、跳转 `/login` 并带回跳参数，同一页面 1 秒内只提示一次
- [x] HTTP `403`：抛 `code = 403` 的错误，页面渲染无权限提示，不自动重试
- [x] 超时统一 10s，抛 `kind = 'timeout'`；网络异常抛 `kind = 'network'`，两者文案不同且都提供重试入口
- [x] 取消请求透传 `AbortSignal`，`kind = 'canceled'` 的异常不进入页面错误态、不弹 Toast
- [x] `upload(url, file)` 封装：`multipart/form-data`，字段名固定 `file`，不手动设置 `Content-Type`；提供 `isApiError(error)` 类型守卫供页面分支

**验收**

- [x] 用 `GET /api/auth/me` 验证 401 分支：令牌被清空并跳转 `/login`
- [x] 业务码非零的响应不进入成功分支
- [x] 取消的请求不渲染错误态

## 1.5 登录态与路由骨架

- [x] `src/stores/auth.ts` 使用 Pinia 定义 `token: string | null` 与 `user: { id, username, nickname, role } | null`，不存放页面数据
- [x] 令牌与用户信息持久化到 `localStorage`，键名 `mall.token`、`mall.user`、`mall.expiresAt`
- [x] `restore()` 在应用启动时读取持久化数据，缺失或解析失败时保持游客态
- [x] `src/router/index.ts` 使用 `createWebHistory`，声明 `/`、`/products`、`/products/:id`、`/login`、`/me`、`/admin`、`/search`、`/seckill`、`/seckill/:activityId`、`/seckill/:activityId/result`、`/orders/:orderNo`、`/403` 与 404 路由，业务页面先指向占位组件
- [x] 路由 `meta.permission` 声明 `public` / `auth` / `admin`，守卫按 `meta` 分支，不按路径字符串硬判断
- [x] 守卫骨架：`auth` 未登录跳 `/login?redirect=<完整路径>`；`admin` 未登录同上，已登录但 `role !== 'ADMIN'` 渲染无权限页
- [x] 参数为 ID 的路由使用 `props: true`，非正整数直接重定向到 404
- [x] 路由切换后滚动到顶部，浏览器前进后退保留滚动位置
