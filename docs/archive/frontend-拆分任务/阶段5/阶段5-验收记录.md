## 1. 联调脚本与原始结果

联调脚本：`tests/e2e/record-phase5.mjs`。以下为真实输出。

### 1.1 新增商品默认下架

```json
{"code":0,"data":{"id":46,"name":"阶段5 商品 1792243990584","price":299,"stock":15,"status":0,"imageUrl":null}}
```

`POST /api/admin/products` 的请求体不含 `status`，响应 `status=0`。

### 1.2 重复上架返回 2002

```json
{"code":2002,"message":"商品已处于「上架」状态","data":null}
```

前端展示后端 `message` 并重新拉取当前页修正行状态，不当作通用失败。

### 1.3 编辑只提交改动字段

请求体：`{"price":279.0}`

```json
{"code":0,"data":{"id":46,...,"price":279,"status":1}}
```

`status` 未被改动，说明编辑接口不接受上下架字段。

### 1.4 管理端列表可查到下架商品

```json
{"code":0,"data":{"total":1,"page":1,"size":5,"list":[{"id":46,...,"status":1}]}}
```

`GET /api/admin/products` 与用户侧 `GET /api/products` 的差异在于前者返回全部状态。

### 1.5 上架前后用户侧可见性

单独脚本 `tests/e2e/verify-status.mjs` 实测（同一商品，先查后上架）：

```text
新增后 status = 0
下架时用户侧 total = 0
上架后用户侧 total = 1
```

新增商品默认下架，用户侧列表不可见；上架后才出现在 `GET /api/products` 结果中。

### 1.6 图片上传

```json
{"code":0,"message":"成功","data":"http://localhost:9000/mall-product/2026/10/17/8bf605b2-b118-4ac3-8a1b-403c9f132bb1.png"}
```

RustFS 正常时返回可直接访问的 URL。

### 1.7 上传伪装成 png 的文本 → 2003

```json
{"code":2003,"message":"只支持 png、jpg、gif、webp 图片","data":null}
```

后端按文件头识别类型。前端本地预校验按 MIME + 扩展名，两者不等价；本例中前端预校验会通过（`Content-Type: image/png`、文件名 `.png`），由后端返回 `2003`，前端按规则原样展示后端文案而不是报成网络错误。

### 1.8 权限

```json
普通用户上传：HTTP 403 {"code":403,"message":"权限不足"}
普通用户重建索引：HTTP 403 {"code":403,"message":"权限不足"}
```

### 1.9 活动表单校验码

```json
{"code":4009,"message":"秒杀价必须低于商品原价","data":null}
{"code":4008,"message":"结束时间必须晚于开始时间","data":null}
{"code":2001,"message":"商品不存在","data":null}   ← 用下架商品建活动
```

前端 `4008` 回填到 `endTime`，`4009` 回填到 `seckillPrice`，`2001` 回填到 `productId`，文案与后端一致。

### 1.10 索引重建

```json
{"code":0,"message":"成功","data":44}
```

`data` 为重建的商品数量，前端展示「已重建 44 条商品索引」。

## 5. 商品表单

| 字段 | 前端校验 | 与后端一致性 |
| --- | --- | --- |
| `name` | trim 后非空，≤128 字符 | `@NotBlank`、`@Size(max=128)` |
| `brand` | ≤64 | `@Size(max=64)` |
| `categoryId` | 正整数 | `@NotNull` |
| `description` | ≤2000 | `@Size(max=2000)` |
| `sellingPoint` | ≤255 | `@Size(max=255)` |
| `price` | ≥0.01，整数位 ≤8，小数位 ≤2 | `@DecimalMin("0.01")`、`@Digits(8,2)` |
| `stock` | ≥0 整数 | `@PositiveOrZero` |
| `imageUrl` | ≤512 | `@Size(max=512)` |

长度按字符数（`[...value].length`）计算，与 Java `@Size` 口径一致；单测用中文字符验证了 128 字符边界。

`price` 用文本输入 + 失焦归一化到两位小数，不用 `type="number"`，避免 `e`、`+`、多位小数被静默接受。

### 5.1 编辑页回填

后端没有管理员单条商品查询接口，`GET /api/products/{id}` 只对已上架商品有效。实测回退路径：按 `size=100` 逐页 `GET /api/admin/products` 遍历到目标 `id`，未命中显示「商品不存在」，与 `2001` 同口径。

### 5.2 只提交改动字段

与初始快照逐字段比较，未改动字段不进请求体；无改动时不发请求并提示「没有需要保存的修改」。实测「只改售价」时请求体仅 `{"price":279.0}`。

### 6.1 活动表单

| 字段 | 前端校验 | 后端依据 |
| --- | --- | --- |
| `productId` | 只能选上架商品 | 上架校验，否则 `2001` |
| `title` | trim 后非空，≤128 | `@NotBlank`、`@Size(max=128)` |
| `seckillPrice` | ≥0.01，≤8 位整数 2 位小数，且低于原价 | `@DecimalMin`、`@Digits`，否则 `4009` |
| `totalStock` | >0 | `@Min(1)` |
| `perUserLimit` | >0，默认 1 | `@Min(1)` |
| `startTime` / `endTime` | 必填，`endTime > startTime` | 否则 `4008` |
| `payTimeoutMinutes` | >0，默认 15 | `@Min(1)` |

### 6.2 时间格式

`datetime-local` 控件输出 `2026-10-17T10:00`，`fromLocalDateTimeInput` 补齐秒得到 `2026-10-17T10:00:00`，不带 `Z` 与时区偏移。单测「两个格式化函数可逆，不会因 UTC 转换偏移 8 小时」验证了 `2026-10-17T10:00:00 → 2026-10-17T10:00 → 2026-10-17T10:00:00`。

明确禁止 `new Date(value).toISOString()`：它按 UTC 输出并带 `Z`，与后端 `LocalDateTime` 语义不符。

## 9. 问题与已知事项

- 后端没有**管理员单条商品**与**单条活动**查询接口，编辑页回填依赖列表快照（`sessionStorage`）或按页遍历。商品量大时遍历成本线性增长。
- `PUT /api/admin/products/{id}` 用 `StringUtils.hasText` 判断 `name`，空串等同不修改，因此名称无法被清空。
- 后端没有商品删除接口，测试数据只能下架，无法物理删除；`record-phase5.mjs` 与 Playwright 用例都以「下架」收尾。
- 后端图片上传按文件头识别类型，与前端 MIME + 扩展名预校验不等价，扩展名伪装的情况由后端 `2003` 兜底。
- 停用进行中活动会按数据库重建 Redis 状态，在途订单的预扣可能丢失，属后端既有行为，前端在确认弹窗中给出警示。
