# 阶段 2 拆分任务

> 目标：完成登录、登录态恢复、商品列表与商品详情，跑通第一条真实数据链路。
> 状态：已完成
> 前置：阶段 1 的 HTTP 客户端、`auth` store、路由守卫骨架、两套布局均已验收；后端 `GET /api/auth/me`、`GET /api/products`、`GET /api/products/{id}` 可访问。

## 2.1 认证接口封装

- [x] `src/api/auth.ts` 定义 `LoginRequest = { username: string; password: string }`，`username` 非空且最长 32，`password` 非空且最长 64，前端校验与后端约束一致
- [x] 定义 `LoginResponse = { token: string; expiresIn: number; user: UserInfo }`，`UserInfo = { id: number; username: string; nickname: string; role: 'USER' | 'ADMIN' }`
- [x] `login(payload)` 调用 `POST /api/auth/login`，返回 `data` 中的 `token`、`expiresIn`、`user`
- [x] `fetchMe()` 调用 `GET /api/auth/me`，返回 `id`、`username`、`nickname`、`role`
- [x] 实现 `1001` 文案映射：展示“用户名或密码错误”，不清空已输入的用户名；实现 `1003` 文案映射：展示“账号已被禁用”，不写入登录态
- [x] 登录成功后由调用方写入 store，接口函数只负责请求与类型，不直接改全局状态

**验收**

- [x] 正确凭据返回 `token`、`expiresIn`、`user`
- [x] 错误密码返回业务码 `1001`，抛出的 `ApiError` 可被页面识别
- [x] 接口函数不出现写死的 Base URL

## 2.2 登录页与表单校验

- [x] `pages/LoginPage.vue` 挂在 `/login`，使用 `SiteLayout`，移动端不出现横向溢出
- [x] 表单字段 `username`、`password`，含 `label`、`autocomplete="username"` 与 `autocomplete="current-password"`
- [x] 前端校验：`username` 非空且 ≤ 32；`password` 非空且 ≤ 64；错误信息在字段下方显示并绑定 `aria-describedby`
- [x] 提交期间禁用提交按钮并显示加载状态，阻止重复提交
- [x] 业务码 `1001` 显示为表单级错误，不跳转页面
- [x] 登录成功后读取 `redirect` 查询参数回跳原路径；`redirect` 缺失、非站内路径或指向 `/login` 时回跳到 `/`；已登录访问 `/login` 直接重定向到 `redirect` 或 `/`
- [x] 页面内不提供“注册”“忘记密码”等后端无对应接口的入口

**验收**

- [x] 空用户名、超长用户名、空密码均在提交前被拦截
- [x] 输入错误密码后停留在登录页且用户名保留
- [x] 从 `/products` 跳登录，成功后回到 `/products`

## 2.3 登录态恢复与退出

- [x] 登录成功写入 `token`、`user` 与 `expiresAt = Date.now() + expiresIn * 1000`
- [x] 应用启动时 `restore()` 读取持久化数据，`expiresAt` 已过期直接清理为游客态
- [x] 刷新页面后 `token` 与 `user` 仍在，`/me` 可直接展示，不闪回登录页
- [x] 令牌存在但 `user` 缺失时调用 `fetchMe()` 补齐，`1002`（用户不存在）或 `401` 时清理登录态
- [x] `logout()` 清除 `token`、`user`、`expiresAt` 与内存状态，跳转 `/`
- [x] `pages/MePage.vue` 挂在 `/me`，展示 `id`、`username`、`nickname`、`role`，`role` 用中文文案（管理员 / 普通用户），并提供经 `ConfirmDialog` 确认的退出登录入口

**验收**

- [x] 登录后刷新 `/me` 仍显示用户信息
- [x] 手工改短 `expiresAt` 后刷新，应用回到游客态且不报错
- [x] 退出后访问 `/me` 跳转 `/login`

## 2.4 路由守卫与 401 / 403

- [x] 守卫读取 `meta.permission`，`auth` 与 `admin` 在未登录时跳转 `/login?redirect=<encodeURIComponent(完整路径)>`
- [x] `admin` 路由在 `role !== 'ADMIN'` 时渲染 `pages/ForbiddenPage.vue`，不跳转登录页
- [x] 此阶段只为 `/admin` 建立一个占位路由做拦截验证，管理端页面在阶段 5 实现
- [x] 401 由 HTTP 客户端统一处理：清态、跳 `/login` 并带回跳参数，不重复弹提示
- [x] 403 渲染“没有访问权限”提示，附带返回首页入口，不自动重试
- [x] 401 与 403 的提示均由同一处逻辑触发，页面内不重复捕获同类错误
- [x] 路由参数校验：`/products/:id` 的 `id` 必须为正整数，否则重定向到 404

**验收**

- [x] 未登录访问 `/admin` 跳转 `/login?redirect=/admin`
- [x] `user` 账号登录后访问 `/admin` 显示无权限页，停留在管理端路径
- [x] 连续触发两次 401 时只显示一次提示

## 2.5 商品接口封装

- [x] `src/api/product.ts` 定义 `Product`：`id`、`name`、`brand`、`categoryId`、`description`、`sellingPoint`、`price`、`stock`、`status`、`imageUrl`
- [x] `brand`、`description`、`sellingPoint`、`imageUrl` 类型为 `string | null`，`status` 为 `0 | 1`
- [x] 定义 `ProductQuery = { page?: number; size?: number; keyword?: string; categoryId?: number }`
- [x] `queryProducts(params)` 调用 `GET /api/products`，返回 `PageResult<Product>`
- [x] 参数约束：`page` 最小 1，`size` 取值 1 到 100，`keyword` 最长 64，`categoryId` 为正数；越界值在请求前收敛到合法范围
- [x] HTTP `400` 与业务码 `400`（请求参数不合法）映射为参数提示，不与网络错误合并
- [x] `fetchProduct(id)` 调用 `GET /api/products/{id}`，返回 `Product`；业务码 `2001` 映射为“商品不可用”，页面据此渲染占位，不当作网络错误

**验收**

- [x] `size=0`、`size=101`、`page=0` 不被原样发出
- [x] 商品 ID 不存在或已下架时抛出业务码为 `2001` 的 `ApiError`
- [x] 响应字段名与 `docs/接口文档.md` 5.1 完全一致

## 本阶段不做

- 不实现购物车、收藏、会员价、收货地址、普通商品订单、商品评价、客服
- 不实现 AI 搜索与搜索框组件（阶段 3）
- 不实现秒杀活动、抢购、轮询与订单（阶段 4）
- 不实现管理端商品与秒杀页面，只在 `/admin` 保留权限守卫占位（阶段 5）
- 不接入远程字体与远程占位图作为首屏依赖
