## 1. 混合搜索实测

### 1.1 自然语言 query

```text
GET /api/search?keyword=夏天穿的透气鞋&page=1&size=5
{"code":0,"message":"成功","data":{"total":10,"page":1,"size":5,"list":[...]}}
```

召回前 5 条（真实返回，非本地过滤）：

| `productId` | name | price | score | hasVector |
| --- | --- | --- | --- | --- |
| 9 | 速干透气洞洞鞋 | 89.00 | 0.03 | true |
| 2 | 夏季透气休闲帆布鞋 | 199.00 | 0.03 | true |
| 7 | 厚底增高老爹鞋 | 259.00 | 0.03 | true |
| 1 | 轻量网面透气跑步鞋 | 399.00 | 0.03 | true |
| 3 | 真皮商务正装皮鞋 | 899.00 | 0.03 | true |

查询串里没有「跑鞋」「帆布鞋」等字面命中词，仍然召回了透气鞋类商品，说明语义召回参与融合。

### 1.2 关键词 query

```text
GET /api/search?keyword=跑鞋&page=1&size=5
```

| `productId` | name | score | hasVector |
| --- | --- | --- | --- |
| 13 | Nike Air Zoom Pegasus 41 | 0.03 | true |
| 14 | 李宁䨻科技跑鞋赤兔 7 Pro | 0.03 | true |
| 2 | 夏季透气休闲帆布鞋 | 0.02 | true |

BM25 与向量两路都返回结果，RRF 融合后按分数排序。

### 1.3 size 上限差异

```text
GET /api/search?keyword=跑鞋&size=100
HTTP 400
{"code":400,"message":"每页条数不能超过 50","data":null}
```

对比商品接口同名参数：

```text
GET /api/products?page=1&size=101
HTTP 400
{"code":400,"message":"每页条数不能超过 100","data":null}
```

搜索 `size` 上限 50、商品上限 100，前端分成 `SEARCH_SIZE_MAX` 与 `PRODUCT_SIZE_MAX` 两个常量，搜索页的 `size` 选项只提供 10 / 20 / 50。单测「搜索接口 size 上限是 50，不复用商品的 100」通过。

## 2. 业务码实测

| 业务码 | 触发方式 | 前端文案 |
| --- | --- | --- |
| `3001` | 通过 `page.route` 注入响应 | 「语义检索暂不可用」+ 「当前搜索依赖语义检索…」 |
| `3002` | 通过 `page.route` 注入响应 | 「搜索服务暂不可用」 |
| 空结果 | 真实查询无命中 | 「没有找到相关商品」 |
| 超时 | 10s 超时分支 | 「搜索超时，请重试」 |
| 网络错误 | `route.abort('failed')` | 「网络异常」 |

`3001`、`3002`、空结果、超时、网络错误五种文案互不相同、互不覆盖。Playwright 用例：
- 「搜索业务码 3002 有独立文案而不是空结果」通过（0.5s）
- 「搜索业务码 3001 与 3002 文案不同」通过（0.5s）
- 「后端不可达时展示网络错误而不是空结果」通过（0.5s，作用于商品列表）

## 3. URL 同步实测

| 行为 | 实测结果 |
| --- | --- |
| 直接访问 `/search?keyword=跑鞋` | 直接出结果，不依赖从首页进入 |
| 提交新关键词 | `router.push` 并重置 `page=1` |
| 翻页 | `push`，前进后退可恢复 |
| 浏览器后退 | 从 `/products` 后退回 `/search`，`keyword` 仍在 URL 上 |
| `page` 非正整数 | `router.replace` 修正 URL，不发非法请求 |
| 无 `keyword` | 不请求，展示「请输入关键词」引导区 |
| 冗余参数 | `page=1` 与默认 `size` 不写入 URL |

Playwright 用例「AI 搜索展示真实召回结果，前进后退可恢复条件」通过（0.8s）。

## 4. 结果渲染

| 检查项 | 实测结果 |
| --- | --- |
| 复用 `ProductCard` | 是，无搜索专用卡片 |
| `:key` 与跳转 | 均读 `productId`，路径 `/products/{productId}` |
| `id` 兜底写法 | 全链路搜索代码中不存在 `item.id ?? item.productId` |
| `score` | 默认不渲染；仅 `import.meta.env.DEV` 或 URL 带 `debug` 时以角标展示 3 位小数 |
| `hasVector` | 默认不渲染；调试开关下对 `false` 标注「仅关键词召回」 |

实测跳转：搜索卡片链接 `href` 形如 `/products/9`，与 `productId` 一致。

## 5. 竞态与边界

| 检查项 | 实测/实现 |
| --- | --- |
| `AbortController` | 每次请求新建，新请求前取消上一次 |
| 递增请求序号 | 旧响应即使返回也不覆盖新结果 |
| 组件卸载 | `onBeforeUnmount` 取消在途请求并递增序号 |
| `page` 越界 | `list` 为空但 `total > 0` 时展示「该页没有结果」+「回到第 1 页」，不静默改 URL |
| 关键字 `trim` | 提交前 `trim`，URL 保存 trim 后的值，全空格视为空 |

单测（`tests/unit/pagination.spec.ts`）覆盖 URL 参数收敛：`size=0→1`、`size=100→50`、`page=0→1`、`keyword` 截断到 128。

## 6. 搜索框组件

| 检查项 | 实测结果 |
| --- | --- |
| 页头与首页共用 | 同一个 `SearchInput.vue`，首页未内联搜索逻辑 |
| 提交 | `trim()` 后非空才 `router.push({ path: '/search', query: { keyword } })` |
| 纯空格提交 | 不跳转、不发请求，输入框保留焦点 |
| `isComposing` | 保留，中文输入法上屏不触发提交 |
| `Escape` | 关闭面板并失焦 |
| `pointerdown` 外部点击 | 关闭面板 |
| `name` 属性 | `keyword`，与接口参数同名（原型为 `q`） |
| 词表 | `["香氛","桌面音箱","原木家具","护肤精华","水洗棉","通勤包"]` 抽为组件 props |
| `<mark>` 高亮 | 保留；命中失败回退「大家常搜」 |
| `maxlength` | 128，粘贴场景再 `slice(0, 128)` |

## 7. 问题与已知事项

- 后端没有搜索建议接口，建议面板只能是本地词表；命中失败展示「大家常搜」而不是空白面板。
- `score` 是 RRF 融合分，跨查询不可比，不折算成「匹配度」百分比。
- 种子数据全部商品 `hasVector=true`，「仅关键词召回」角标在调试模式下未触发到 `false` 分支。
- 搜索接口的 `size` 默认值是 10，页面默认同样是 10，所以默认请求 URL 不带 `size`。
