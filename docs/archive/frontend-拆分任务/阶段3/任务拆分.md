# 阶段 3 拆分任务

> 目标：把原型的本地搜索建议升级为真实 BM25 + 向量语义 + RRF 融合搜索，产出可联调的 `/search` 页面。
> 状态：已完成
> 前置：阶段 2 已验收（HTTP 客户端、`ProductCard`、分页与空状态组件可用）；后端阶段 3 搜索接口已验收。

## 3.1 搜索接口封装

- [x] 新增 `src/api/search.ts`，导出 `searchProducts(params)`，请求 `GET /api/search`
- [x] 入参类型 `SearchQuery`：`keyword`、`page`、`size`
- [x] `keyword` 必填，非空，最长 128；`page` 默认 `1`，最小 `1`；`size` 默认 `10`，取值 1 到 50
- [x] 出参条目类型 `SearchHit` 字段逐字对齐接口文档：`productId`、`name`、`brand`、`categoryId`、`sellingPoint`、`price`、`stock`、`imageUrl`、`score`、`hasVector`
- [x] 分页结构复用阶段 1 的 `PageResult<T>`：`total`、`page`、`size`、`list`
- [x] 查询串用 `URLSearchParams` 组装，可选参数不传时不写进 URL
- [x] 业务码 `3001`、`3002` 原样上抛为阶段 1 的可识别业务错误，api 层不改写文案

**说明**：搜索的 `size` 上限是 50，商品接口与秒杀活动接口是 100，不复用同一份分页常量，避免把 100 传给搜索接口被后端以「请求参数不合法」拒绝。

**验收**

- [x] 请求 URL 与 `docs/接口文档.md` 6.1 一致
- [x] 类型定义中没有 `id` 字段冒充搜索结果主键
- [x] `size=100` 在类型或校验层就被拦住，不会发到后端

## 3.2 搜索框组件

- [x] 新增 `src/components/SearchInput.vue`，页头与首页共用同一个组件，首页不内联搜索逻辑
- [x] 组件对外只暴露 `submit(keyword)`：`trim()` 后非空才 `router.push({ path: '/search', query: { keyword } })`
- [x] 复用原型 2834–2852：`role="search"` 表单、`sr-only` 标签、图标按钮、清空按钮、`aria-controls` 指向建议面板、面板 `role="listbox"`
- [x] 复用原型 3974–4118 的交互：输入本地过滤、`aria-expanded` 同步、`Enter` 提交（保留 `event.isComposing` 判据，避免中文输入法上屏即提交）、`Escape` 关闭并失焦、`pointerdown` 点击表单外部关闭
- [x] 改造：原型的 `submitSearch` 只弹 Toast，改为路由跳转
- [x] 改造：`input` 的 `name="q"` 改为 `name="keyword"`，与接口参数同名
- [x] 改造：硬编码词表 `["香氛", "桌面音箱", "原木家具", "护肤精华", "水洗棉", "通勤包"]` 保留为本地建议来源，抽成组件属性，不再写死在脚本里
- [x] 保留 `<mark>` 高亮命中片段的实现，匹配不到时回退到常搜词
- [x] `keyword` 超长：输入框 `maxlength="128"`，粘贴场景再 `slice(0, 128)`
- [x] 清空按钮保留原型的可见性切换与焦点回填

**说明**：后端没有搜索建议接口，建议面板只能是本地词表；命中失败时展示「大家常搜」而不是空白面板。

**验收**

- [x] 页头与首页搜索行为一致，提交后都跳到 `/search?keyword=...`
- [x] 纯空格提交不跳转、不发请求，输入框保留焦点
- [x] 键盘 `Escape` / `Enter` 与鼠标点击外部行为均可复现
- [x] 首页组件中没有出现 `searchProducts` 调用

## 3.3 搜索页与 URL 同步

- [x] 新增 `/search` 路由与 `src/pages/search/SearchPage.vue`
- [x] `keyword`、`page` 全部来自 `route.query`，页面不另存一份分页状态
- [x] 挂载时按当前 `route.query` 发起请求；`watch` 路由查询变化重新请求
- [x] 直接访问 `/search?keyword=夏天穿的透气鞋&page=2` 能直接出结果，不依赖从首页进入
- [x] 提交新关键词用 `router.push` 并重置 `page=1`；翻页也用 `push`，保证前进后退可用
- [x] `/search` 无 `keyword`：不请求，展示「请输入关键词」引导区
- [x] `page` 非正整数：回退为 `1`，并用 `router.replace` 修正 URL 而不是发出非法请求
- [x] 页面标题与搜索框回填当前 `keyword`

**说明**：搜索条件只信 URL，不新建第二份状态，浏览器前进后退才不需要额外同步代码。

**验收**

- [x] 前进、后退能恢复关键词与页码，刷新页面结果不丢
- [x] 带参数直接访问可出结果
- [x] URL 上不出现 `page=1` 之外的冗余参数

## 3.4 结果渲染

- [x] 结果列表复用阶段 2 的 `ProductCard`，不做搜索专用卡片
- [x] `:key` 与跳转都读 `productId`，详情路径 `/products/{productId}`
- [x] 卡片映射：`name`、`brand`、`sellingPoint`、`price`、`stock`、`imageUrl`；`categoryId` 仅作为展示或调试信息
- [x] `score` 默认不渲染；仅在 `import.meta.env.DEV` 或 URL 带调试开关时以角标显示，保留 3 位小数
- [x] `hasVector` 默认不渲染；调试开关下对 `hasVector === false` 标注「仅关键词召回」
- [x] 结果区展示当前结果条数与 `total`
- [x] 图片加载失败走阶段 2 的占位兜底，不出现破图

**说明**：`score` 是 RRF 融合分，跨查询不可比，展示成「匹配度」会误导用户；`hasVector` 只表示该文档有没有语义向量，不是商品质量或 AI 评分。`hasVector` 缺失或为 `null` 时按未知处理，不做标注。

**验收**

- [x] 全链路只出现 `productId`，没有 `id` 兜底写法（如 `item.id ?? item.productId`）
- [x] 点击任意结果进入对应商品详情
- [x] 用户可见区域不出现 `score` 与 `hasVector`

## 3.5 三类状态

- [x] 页面状态枚举：`idle`、`loading`、`success`、`empty`、`error`
- [x] `error` 细分：`3001`、`3002`、超时、网络错误、其他非零业务码
- [x] `3001` → 「语义检索暂不可用」，附「当前搜索依赖语义检索，请稍后重试」与重试按钮
- [x] `3002` → 「搜索服务暂不可用」，提供重试按钮
- [x] 空结果 → 「没有找到相关商品」，给关键词改写建议与「返回首页」
- [x] 加载中 → 结果区骨架卡片，不展示空态文案
- [x] 请求超时 → 「搜索超时，请重试」，与网络错误文案区分
- [x] 网络错误 → 「网络异常，请检查网络后重试」
- [x] 状态区使用 `role="status"` 与 `aria-live="polite"` 播报

**说明**：只有 `code === 0` 且 `list` 为空才允许进入空态。任何失败路径都不得渲染「没有找到相关商品」，这是本阶段最容易写错的边界。

**验收**

- [x] `3001`、`3002`、空结果、超时、网络错误五种文案互不相同、互不覆盖
- [x] 断开后端时页面显示服务不可用，而不是「没有商品」
- [x] 重试按钮只重发当前查询，不改变 URL 条件

## 3.6 分页与边界

- [x] 分页条复用阶段 2 组件，`size` 选项只提供 10、20、50
- [x] `page` 越界（`list` 为空但 `total > 0`）展示「该页没有结果」并提供「回到第 1 页」，不静默改 URL
- [x] 关键字提交前 `trim()`，URL 中保存 `trim` 后的值；全空格视为空关键词
- [x] 每次请求创建 `AbortController`，新请求发出前取消上一次
- [x] 用递增请求序号忽略过期响应，旧请求即使返回也不覆盖新结果
- [x] 组件卸载、路由离开时取消在途请求
- [x] 连续快速提交不同关键词只保留最后一次结果，不出现闪回

**验收**

- [x] 快速连打三次搜索，最终列表与最后一次关键词一致
- [x] 翻页过程中切换关键词不出现旧页数据残留
- [x] 页码 0 或负数不会发到后端

## 阶段验收

- 不把 `score` 做成用户可见评分
- 不接入 `POST /api/admin/search/reindex`，属于阶段 5
