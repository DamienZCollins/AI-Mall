# 阶段 0：仓库与环境

## 目标

统一 Git、环境变量和本地中间件启动方式，为后续 Spring Boot 骨架提供可复现的开发环境。

## 本地依赖

| 依赖 | 镜像 | 用途 |
| --- | --- | --- |
| MySQL | `mysql:8.4` | 业务数据 |
| Redis | `redis:7-alpine` | 缓存、秒杀库存和幂等 |
| RocketMQ | `apache/rocketmq:5.3.2` | 异步下单和延迟消息 |
| Elasticsearch | `docker.elastic.co/elasticsearch/elasticsearch:8.15.3` | 关键词及向量搜索 |
| RustFS | `rustfs/rustfs:latest` | 商品图片，S3 协议兼容，MinIO 停止开源后的替代 |

所有服务由 `docker-compose.yml` 编排，数据使用 Docker named volume 持久化。RocketMQ 使用单 NameServer + 单 Broker 的开发拓扑；Elasticsearch 在本地关闭安全认证，仅用于开发，生产环境不得照搬。

## 环境变量

1. 复制 `.env.example` 为 `.env`。
2. 本地可以使用模板默认值；共享环境或生产环境必须替换密码。
3. `.env` 已被 `.gitignore` 忽略，不提交真实密钥。
4. 应用配置参考 `config/application.yml.example`，业务代码不得硬编码连接地址和凭据。

## 启动与验收

```bash
cp .env.example .env
docker compose up -d
./scripts/check-dependencies.sh
```

检查容器状态：

```bash
docker compose ps
```

停止但保留数据：

```bash
docker compose down
```

删除数据：

```bash
docker compose down -v
```

## 约定

- 包名、类名、变量名使用英文。
- 注释和文档使用中文，注释只描述做了什么。
- 按“模块优先、模块内分层”组织 Spring Boot 代码。
- 每次提交遵循 `<type>: <精炼描述>`，尽量控制在 50 行左右。
- 阶段 0 不引入业务代码；阶段 1 再初始化 Java 工程。
