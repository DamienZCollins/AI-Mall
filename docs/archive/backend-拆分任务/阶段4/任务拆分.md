# 阶段 4 拆分任务

> 目标：先不考虑高并发，把秒杀业务和数据库约束做正确——不超卖、不重复下单、超时可回补。
> 状态：已完成（2026-10-02）
> 本阶段不引入 Redis 与 RocketMQ，全部靠数据库约束承载；阶段 5 再升级为异步模型。

## 4.1 秒杀表结构

- [x] `seckill_activity` 表：绑定商品、秒杀价、开始与结束时间、活动状态
- [x] `seckill_stock` 表：`activity_id` 唯一，`stock` 带 `stock >= 0` 约束
- [x] `seckill_order` 表：`user_id + activity_id` 唯一索引，防重复下单
- [x] `seckill_order` 记录 `expire_time`，供超时取消使用
- [x] 建表语句追加到 `sql/schema.sql`，可重复执行

**验收**

- [x] 三张表均可重复执行建表
- [x] `stock` 字段有非负约束，非法值写不进去
- [x] `user_id + activity_id` 唯一索引生效

## 4.2 活动时间校验与状态

- [x] `SeckillStatus` 由当前时间与活动时间推导：未开始 / 进行中 / 已结束
- [x] 活动创建时校验 `end_time > start_time`、秒杀价低于商品原价
- [x] 活动状态与时间窗口不一致时下单被拒绝
- [x] 未开始与已结束分别返回可区分的错误码

**验收**

- [x] 未开始的活动不能下单
- [x] 已结束的活动不能下单
- [x] 时间窗口内的活动可以下单

## 4.3 活动管理接口

- [x] `SeckillActivity`、`SeckillStock` 实体与 Mapper
- [x] `AdminSeckillController`：创建活动（同时初始化库存行）、编辑、分页查询
- [x] `SeckillController`：用户侧查询进行中的活动
- [x] 创建活动时校验商品存在

**验收**

- [x] ADMIN 可创建与编辑活动
- [x] USER 访问管理端返回 403
- [x] 活动创建后库存行自动建立

## 4.4 同步下单

- [x] `POST /api/seckill/{activityId}` 同步下单接口
- [x] 先校验活动时间窗口与状态，再写入订单
- [x] `SeckillOrder` 实体与 Mapper，订单号唯一
- [x] 订单状态初值为待支付，`expire_time` 为下单时间加配置的超时分钟数
- [x] 同一用户同一活动重复下单由唯一索引拦截，返回业务错误

**验收**

- [x] 时间窗口内下单成功，返回订单号与支付截止时间
- [x] 同一用户重复下单返回业务错误码，不产生第二条订单
- [x] 非法活动 ID 返回活动不存在

## 4.5 数据库条件更新防超卖

- [x] 库存扣减使用 `UPDATE ... SET stock = stock - 1 WHERE activity_id = ? AND stock > 0`
- [x] 依据影响行数判断扣减是否成功，为 0 说明已售罄
- [x] 扣减失败时订单事务回滚，不产生无库存的订单
- [x] 扣减放在订单写入之后，保证重复下单不会白扣库存

**验收**

- [x] 库存为 0 后再下单返回已售罄
- [x] 并发小规模压测下不超卖，成功订单数等于活动库存

## 4.6 订单状态机

- [x] `SeckillOrderStatus`：待支付 / 已支付 / 已取消 / 超时取消
- [x] 只允许「待支付 → 已支付」「待支付 → 已取消」「待支付 → 超时取消」
- [x] 非法流转被拒绝，已支付订单不能取消
- [x] `POST /api/seckill/orders/{orderNo}/pay` 模拟支付回调

**验收**

- [x] 待支付订单可支付
- [x] 已支付订单再次支付被拒绝
- [x] 已支付订单取消被拒绝

## 4.7 超时取消与库存回补

- [x] 定时任务扫描超过 `expire_time` 且仍待支付的订单
- [x] 用条件更新把状态流转为超时取消，影响行数为 1 才回补库存
- [x] 库存回补与状态流转在同一事务内完成
- [x] 回补时校验库存不超过活动总量

**验收**

- [x] 超时订单自动置为超时取消
- [x] 取消后库存回补，商品可再次被下单
- [x] 定时任务重复执行不会重复回补

## 4.8 并发正确性验证

- [x] 用多线程并发下单验证不超卖
- [x] 用多线程同用户并发下单验证不重复
- [x] 记录真实结果，不编造数据
- [x] 更新本文档

**验收**

- [x] 库存 10、50 并发请求，成功数恰为 10，库存归零
- [x] 同一用户 20 并发请求，只产生 1 条订单
- [x] 验收数据真实记录
