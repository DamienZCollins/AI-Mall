# 本地中间件启动与验收记录

> 记录时间：2026-10-02
> 环境：Windows + Docker Desktop（Linux 容器，Compose v5.5.1）

## 1. 启动方式

```bash
# 首次：复制环境变量模板并填写真实值
copy .env.example .env

# 启动全部中间件
docker compose up -d

# 查看状态
docker compose ps

# 停止（保留数据卷）
docker compose down
```

`rocketmq-broker-init` 是一次性容器，负责把 broker 数据卷属主改为 `3000:3000`，执行完即退出，属正常现象。

### 重启复验

执行 `docker compose down` 后再次 `docker compose up -d`：

- 全部服务恢复健康
- MySQL、Elasticsearch、RustFS 数据卷保留
- RocketMQ 再次收发消息 `SEND_OK`
- Dashboard 再次查询集群 `status=0`

## 6. 已知事项

- RocketMQ 镜像默认堆内存较大，已在 compose 中通过 `HEAP_OPTS` 下调。
- Dashboard 2.1.x 实际监听 `8082`，compose 按 `8082` 映射到宿主机 `18080`。
- `brokerIP1=host.docker.internal` 供宿主机应用访问；容器内应用后续可通过服务名 `rocketmq-broker` 访问。
- 本地开发统一使用固定凭据：MySQL `dev/1234`（root 同密码）、RustFS `dev/1234`；Redis 仅本地开发使用，不设密码。真实环境需替换全部密码并启用 Redis 认证。
