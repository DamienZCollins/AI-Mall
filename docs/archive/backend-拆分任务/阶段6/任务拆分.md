**说明**

基线取 `0cd8aed`（接入 RocketMQ gRPC 客户端），这是最后一个「纯数据库同步下单」的提交，

（`git diff 0cd8aed HEAD -- sql/` 为空），因此能直接连同一套库。

两个版本共用同一套 MySQL / Redis / RocketMQ，只在切换时换应用进程，不并行运行。

## 6.3 同步版本基线压测

- [x] 测试一 突发抢购：库存 100 / 用户 400 / 并发 400 / ramp-up 1s
- [x] 测试二 阶梯加压：库存 2000 / 用户 2000 / 并发 50 → 100 → 200 → 400
- [x] 测试三 售罄后流量：售罄后用未下单的 300 用户持续打 30s
- [x] 每档正式测量前先跑一轮预热，结果不计入
- [x] 记录客户端指标：QPS、平均、P50 / P95 / P99、最大、错误率与错误码分布
- [x] 记录服务端指标：应用与 MySQL / Redis 容器 CPU 与内存、MySQL `Threads_running`、GC
- [x] 写下瓶颈结论

**说明**

测试三是秒杀的真实形态：库存早就没了，绝大多数请求都在打空枪。
售罄请求不改变任何状态，可以持续重复打，不会耗尽账号。

**验收**

- [x] 数据真实，每档重复 2 次以上并给出离散度
- [x] 能指出同步版本的瓶颈在哪里、依据是什么
