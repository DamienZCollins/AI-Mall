> 记录时间：2026-10-02
> 环境：Windows + Java 21（Liberica 21.0.4）+ Spring Boot 3.5.16

## 1. 验收命令

```bash
# 建表与初始化数据
docker exec -i mall-mysql mysql -uroot -p1234 --default-character-set=utf8mb4 mall < sql/schema.sql
docker exec -i mall-mysql mysql -uroot -p1234 --default-character-set=utf8mb4 mall < sql/data.sql

# 构建
mvn clean package -DskipTests

# 启动（数据库与对象存储凭据来自 .env）
set -a && . ./.env && set +a
java -jar target/mall-0.0.1-SNAPSHOT.jar

# 接口验收（35 项检查）
python scripts/checks/api_check.py
```

`scripts/checks/api_check.py` 用 Python 发起请求而非直接在终端拼 curl，原因是本机终端为 GBK 编码，直接写中文请求体会被破坏成非法 UTF-8。

## 5. 过程中修正的问题

| 问题 | 现象 | 处理 |
| --- | --- | --- |
| JWT 密钥解析 | 启动失败 `Illegal base64 character: '-'` | `Decoders.BASE64.decode` 抛的是 `DecodingException`，原先按 `IllegalArgumentException` 兜底的分支不会生效；改为直接按 UTF-8 字节派生密钥 |
| Bean 循环依赖 | 启动失败，`jwtAuthenticationFilter` 与 `securityConfig` 互相依赖 | `PasswordEncoder` 从 `SecurityConfig` 拆到独立的 `PasswordConfig`，切断 `UserService → SecurityConfig` 这条边 |
| 方法级鉴权返回 500 | USER 角色访问管理端返回 `{"code":500}` | `@PreAuthorize` 拒绝时抛 `AuthorizationDeniedException`，它不经过 `ExceptionTranslationFilter`，被兜底处理器捕获；在 `GlobalExceptionHandler` 中单独处理为 403 |
| `user` 是 MySQL 保留字 | 直接建表会报语法错误 | 用户表命名为 `sys_user` |

## 6. 已知事项

- 数据库表结构通过 `sql/` 下的脚本手工执行，未引入迁移工具；阶段 3 新增索引相关表结构时沿用同一方式。
- 商品图片当前只有单个 `image_url` 字段，多图能力推迟到确有需要时再加。
- bucket 的匿名读策略在应用启动时写入，只放开 `s3:GetObject`；生产环境应改为走 CDN 或签名 URL。
- `/api/products` 只按名称与品牌做模糊匹配，真正的混合检索在阶段 3 由 Elasticsearch 承担。
