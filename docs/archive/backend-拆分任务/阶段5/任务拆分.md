# 阶段 5 拆分任务

> 目标：把秒杀链路从数据库同步模型升级为 Redis 预扣 + RocketMQ 异步下单。
> 状态：已完成（2026-10-02）
> 阶段 4 的数据库约束全部保留，作为最后一道防线；本阶段在其前面加一层快速通道。

## 5.1 引入 Redis 与 RocketMQ

- [x] `pom.xml` 引入 `spring-boot-starter-data-redis` 与 `rocketmq-client-java` 5.0.7
- [x] docker-compose 增加 `rocketmq-proxy` 服务，gRPC 端口 8081
- [x] 新增 `scripts/infra/init-rocketmq-topics.sh` 建主题
- [x] 主题 `mall-seckill-order` 声明支持 DELAY 消息类型
- [x] 应用配置补充 Redis 与 RocketMQ 连接项

**验收**

- [x] 代理启动后客户端能连通
- [x] 延迟消息按设定时间投递
- [x] 未建主题时错误信息能指向解决办法

## 5.2 活动库存预热

- [x] Redis Key 规划：库存、买家集合、活动元数据、活动总量
- [x] `SeckillRedisService` 封装预热、查询与清理
- [x] 活动创建后自动预热
- [x] 应用启动时预热未结束的活动
- [x] 库存 Key 不存在时按需预热，避免重启后失效
- [x] 预热从数据库完整重建：库存取库存表，买家集合按该活动已有订单行回填
- [x] 预热加短锁收敛并发，避免多个请求互相删除对方刚写入的状态

**验收**

- [x] 活动创建后 Redis 中出现库存键，值与活动总量一致
- [x] 应用重启后进行中的活动仍可下单
- [x] 清空 Redis 后重建，已下单用户仍被拦住且两侧库存一致（无泄漏）

## 5.3 Redis Lua 原子预扣

- [x] `lua/seckill_deduct.lua` 在一次原子操作内完成：活动时间校验、库存判断、用户去重、扣减、记录买家
- [x] 脚本用预计算的毫秒时间戳比较，避免 Lua 内处理日期
- [x] 返回可区分的状态码：成功 / 未开始 / 已结束 / 售罄 / 重复下单
- [x] 库存扣减到 0 时写售罄标记

**验收**

- [x] 同一用户并发请求只成功一次
- [x] 库存扣完后返回售罄
- [x] 活动时间窗口外返回对应错误

## 5.4 投递消息与失败补偿

- [x] `POST /api/seckill/{activityId}` 改为 Redis 预扣 + 发送 MQ
- [x] 发送成功立即返回「排队中」
- [x] 发送失败时回补 Redis 库存并移除买家标记，返回可重试的错误
- [x] 投递失败场景有明确错误码，不静默丢单

**验收**

- [x] 正常路径返回排队中
- [x] MQ 不可用时库存能回补，用户可再次下单

- [x] `OrderCreateConsumer` 消费并创建订单
- [x] 消费幂等：唯一索引冲突视为已处理，返回成功
