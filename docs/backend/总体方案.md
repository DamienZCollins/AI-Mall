# Mall 总体方案

> 一个以“AI 混合搜索 + 高并发秒杀”为核心亮点的模块化单体商城 

## 1. 项目定位

- 核心亮点：
  1. 普通商品搜索：Elasticsearch BM25 + 向量语义检索 + RRF 混合排序
  2. 秒杀模块：Redis Lua 预扣库存 + RocketMQ 异步下单 + 防超卖/幂等/超时回补
  3. 压测体系：JMeter 阶梯加压 + 秒杀链路瓶颈定位 + 优化前后指标对比

## 2. 领域建模

只列核心对象，纯 CRUD 不展开

### 核心对象

- 用户：买家/管理员
- 商品：普通商品，可被搜索
- 秒杀活动：绑定商品，独立库存和时间段
- 订单：用户下单结果，包含普通订单和秒杀订单
- 支付：模拟支付回调

### 状态流转

订单：

```text
待支付 -> 已支付 -> 已取消 / 超时取消
```

秒杀活动：

```text
未开始 -> 进行中 -> 已结束
```

## 4. 数据设计

只列表名、职责和关键索引，详细字段在编码时补充。


| 表                | 职责     | 关键约束/索引                        |
| ---------------- | ------ | ------------------------------ |
| sys_user         | 用户基础信息 | username 唯一；user 是 MySQL 保留字，故加前缀 |
| product          | 商品基础信息 | status、category_id             |
| seckill_activity | 秒杀活动   | product_id、start_time、end_time |
| seckill_stock    | 秒杀库存   | activity_id 唯一，stock > 0       |
| orders           | 普通订单   | order_no 唯一，暂未实现               |
| seckill_order    | 秒杀订单   | user_id + activity_id 唯一       |
| payment          | 支付记录   | order_no 唯一，暂未实现               |




## 5. 接口设计

### 搜索

- `GET /api/search`
  - 入参：`keyword`
  - 出参：商品列表
  - 说明：BM25 + 向量召回，RRF 融合

### 秒杀

- `POST /api/seckill/{activityId}`
  - 入参：路径参数
  - 出参：排队/成功/失败
  - 说明：Redis 预扣库存，成功后投递 MQ
- `GET /api/seckill/{activityId}/result`
  - 出参：秒杀结果
  - 说明：前端轮询订单创建结果

不把请求受理直接当作抢购成功。购物车、收货地址、会员与商品评价不在范围内。
