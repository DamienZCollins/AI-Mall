# 开发路径

> 目标：先跑通最小闭环，再做两个核心亮点，最后用压测验证效果。
> 原则：每一步都有可运行产物，避免长期停留在文档和架构设计阶段。

## 阶段 0：仓库与环境

### 目标

把本地开发环境和基础工程规范确定下来。

### 任务

- 初始化 Git 仓库
- 编写 `AGENTS.md`
- 确定本地依赖：MySQL、Redis、RocketMQ、Elasticsearch、RustFS
- 准备 `docker-compose.yml` 管理本地中间件
- 建立统一配置文件结构

### 产出

- 可一键启动的本地依赖
- 项目编码约定
- 环境变量模板

### 验收

- 中间件可以本地启动
- 配置不硬编码，敏感信息不进入 Git

---

## 阶段 1：Spring Boot 骨架

### 目标

先得到一个能启动、能访问接口文档的空业务系统。

### 任务

- 初始化 Spring Boot 3 工程
- 使用 Java 21
- 建立模块化分包：`common / user / product / search / seckill / order / config`
- 实现统一返回体
- 实现统一异常处理
- 接入 springdoc-openapi
- 配置 MyBatis-Plus 和 MySQL

### 产出

```text
GET /actuator/health
GET /v3/api-docs
```

### 验收

- 应用可启动
- OpenAPI 文档可访问
- 数据库连接正常

---

## 阶段 2：基础用户与商品模块

### 目标

只做支撑两个核心模块的最小基础功能。

### 任务

- 用户表
- USER / ADMIN 两种角色
- JWT 登录
- 商品表
- 管理员商品新增、编辑、上下架
- 接入 RustFS，实现商品图片上传（S3 协议）
- 用户查询商品列表和详情

### 明确不做

- 复杂权限系统
- 会员体系
- 收货地址管理
- 复杂类目树
- 商品评价

### 产出

- 用户登录接口
- 商品 CRUD 接口
- 基础测试数据

### 验收

- 管理员可维护商品
- 用户可查看商品
- 商品状态能控制是否对外展示
- 商品图片可上传并可通过 URL 访问

---

## 阶段 3：AI 混合搜索闭环

### 目标

完成第一个核心亮点：普通商品的关键词 + 语义混合搜索。

### 任务

- 设计商品搜索索引 mapping
- 组装商品 embedding 文本：标题 + 品牌 + 分类 + 卖点 + 描述
- 接入 OpenAI 兼容 embedding 接口
- 商品入库 / 更新时同步 ES 索引
- 实现 BM25 关键词检索
- 实现 dense_vector 语义检索
- 使用 RRF 融合两路结果
- MySQL 补充价格、库存、状态等业务字段
- 搜索结果支持基础分页
- 搜索结果返回商品图片 URL

### 产出

- `GET /api/search`
- ES mapping
- embedding 客户端
- 商品同步链路

### 验收

- 搜索“夏天穿的透气鞋”能召回网面鞋、跑步鞋等语义相关商品
- 搜索品牌或型号时关键词检索表现稳定
- 两路结果经 RRF 融合后排序合理
- 下架商品不出现在搜索结果中

---

## 阶段 4：秒杀正确性版本

### 目标

先不考虑高并发，把秒杀业务和数据库约束做正确。

### 任务

- 设计秒杀活动表
- 设计秒杀库存表
- 设计秒杀订单表
- 实现活动时间校验
- 实现普通同步下单
- 使用数据库条件更新防止超卖
- 使用唯一索引防止重复下单
- 设计订单状态机

### 产出

- 秒杀活动管理接口
- 同步秒杀下单接口
- 订单状态流转

### 验收

- 库存为 0 后不能再下单
- 同一用户同一活动只能下一单
- 非法状态流转被拒绝
- 并发小规模测试下不超卖

---

## 阶段 5：秒杀高并发优化

### 目标

把秒杀链路升级为 Redis + RocketMQ 的异步模型。

### 任务

- 活动开始前预热库存到 Redis
- 编写 Redis Lua 脚本：原子扣减库存 + 用户去重
- 秒杀请求成功后投递 RocketMQ
- 消费者异步创建订单
- MySQL 条件更新兜底防超卖
- 实现秒杀结果轮询接口
- 使用延迟消息处理订单超时取消
- 超时后回补库存
- 设计幂等消费逻辑

### 产出

- `POST /api/seckill/{activityId}`
- `GET /api/seckill/{activityId}/result`
- Lua 脚本
- MQ 生产者和消费者

### 验收

- 大量重复请求下不重复下单
- Redis 或 MQ 异常时系统不进入不可恢复状态
- 订单超时未支付自动取消
- 取消订单后库存可回补
- 全链路无超卖

---

## 阶段 6：压测与优化

### 目标

用真实数据验证秒杀模块，并沉淀面试可讲的问题和优化过程。

### 任务

- 使用 JMeter 编写秒杀压测脚本
- 压测同步版本和优化版本
- 记录 QPS、平均响应时间、P95 / P99、错误率
- 观察 MySQL、Redis、RocketMQ 压力
- 针对瓶颈逐项优化
- 输出压测报告

### 产出

- `docs/压测报告.md`
- 优化前后对比数据

### 验收

- 压测数据真实可复现
- 能解释每个主要瓶颈和对应优化
- 不为了数字牺牲正确性

---

## 阶段 7：收尾与面试表达

### 目标

把项目整理成能展示、能讲述、能被追问的作品。

### 任务

- 补充核心接口 OpenAPI 注解
- 整理项目启动说明
- 准备核心设计讲解
- 梳理 AI 协作流程
- 复盘踩坑和优化过程

### 面试重点讲清

- 为什么 BM25 和向量检索都要保留
- 为什么使用 RRF
- 为什么 ES 适合这个项目的混合搜索
- 为什么 Redis Lua 能防止超卖
- 为什么要异步下单
- MQ 消息重复或丢失怎么办
- 订单超时取消和库存回补如何保证一致性
- 压测瓶颈在哪里、如何优化

---

## 阶段 8：前端设计沉淀

### 目标

把原型与设计约束归入文档，供后续前端实现与联调参考。

### 任务

- 整理用户侧与管理端静态原型
- 沉淀配色、字体、间距等设计令牌
- 记录路由、分页、表单校验与失败恢复约定
- 运行静态审计并保留结果

### 产出

- `docs/前端设计/静态原型.html`
- `docs/前端设计/设计系统.md`
- `docs/前端设计/交互契约.md`
- `docs/前端设计/审计记录.json`

### 验收

- 原型可直接用浏览器打开，无外部资源依赖
- 页面覆盖 AI 搜索、秒杀、订单与商品管理
- 设计令牌与交互约定有明确归属文件

---

## 建议分支与提交策略

- 开发主干使用 `main`
- 每个阶段可以建短期功能分支，例如 `feature/spring-boot-skeleton`
- 每完成一个可运行闭环就合并回 `main`
- 提交粒度按功能划分，避免巨型提交
